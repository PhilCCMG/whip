# Dev setup notes (Stage B tooling)

Non-obvious tooling choices and workarounds, verified on 2026-10-24 (Windows 11, Node 24.15, pnpm 10.33).

## Workspace and TypeScript

- Internal packages export TS source (`"exports": { ".": "./src/index.ts" }`), with no build step.
  Relative imports are extensionless (`moduleResolution: bundler`).
- No project references. Each package runs `tsc --noEmit` against its own tsconfig, which extends
  `@whip/config/tsconfig.base.json`. The root `tsconfig.json` exists only so ESLint's project
  service can type the root `vitest.config.ts`.
- `apps/api/worker-configuration.d.ts` is generated by `wrangler types` and **committed** (CI
  typechecks without running wrangler). Rerun `pnpm cf-typegen` after binding changes.
  `src/env.ts` wraps it: `Env = Omit<Cloudflare.Env, 'DEV_AUTH' | 'BETTER_AUTH_SECRET'> & optional
  secrets`, so it stays valid whether or not a `.dev.vars` existed when types were generated.
- `@types/node` is included in apps/api because `nodejs_compat` is on (Better Auth needs `node:` APIs).

## ESLint

- **ESLint 10 resolves config per file** (nearest `eslint.config.*`). For that reason the shared
  preset is `packages/config/eslint-preset.js`, *not* `eslint.config.js`. Otherwise files in
  packages/config pick it up as their config. There is one root `eslint.config.js`.
- Dependency direction uses `@typescript-eslint/no-restricted-imports`, which supports
  `allowTypeImports` for web → domain type-only. Flat-config rules with the same name *replace*
  each other, so every package glob gets exactly one composed rule (see `boundaries` in the
  preset). This replaces the `dependency-cruiser` check mentioned in 01-overview §2. ESLint covers
  the same rules with less tooling. Add dependency-cruiser later if cycle detection is wanted.
- Purity bans (`no-restricted-globals` / `no-restricted-properties`) apply to
  `packages/{simulation,domain}/**` except `*.test.ts`, `*.bench.ts`, `test/`, `tests/`. In
  simulation, test files may also import `@whip/content`. Verified by probe files: `Math.random()`,
  `Date.now()`, `new Date()`, `performance`, `globalThis.crypto`, `setTimeout`, `react` and
  `@whip/content` all fail lint in `simulation/src`.

## Prettier

`*.jsonc` uses `trailingComma: none` so `wrangler.jsonc` stays readable by strict JSONC readers.
`docs/` is excluded from Prettier (the approved docs are hand-formatted).

## Wrangler / Workers

- **DO migration form**: classic `migrations: [{ tag: "v1", new_sqlite_classes: ["CampaignDO"] }]`,
  repeated in each named env (bindings and migrations are not inherited). Works with wrangler
  dev, dry-run deploy and the vitest plugin.
- `compatibility_flags: ["nodejs_compat"]` is kept for Better Auth (AsyncLocalStorage etc.).
- **Assets directory must exist** or wrangler dev, `deploy --dry-run` and the vitest plugin refuse
  to start. `scripts/ensure-web-dist.mjs` writes a placeholder `apps/web/dist/index.html` if the SPA
  hasn't been built. It runs from api `dev`/`build` and integration `pretest`.
- `pnpm build` bundles with `--env production`, so the dry-run checks the real production bindings.
- The **top level of wrangler.jsonc is local-only** (`whip-local`, `workers_dev: false`,
  `whip-core-local` / `whip-saves-local`, `DEV_AUTH=1`). Deploys always pass `--env`
  (`pnpm deploy:staging|production`, CI); `triggers.crons` is repeated in every env.
- Local D1 `database_id` is a zero-UUID placeholder. Staging/production IDs are placeholders until
  provisioning (infrastructure/cloudflare/README.md).

## D1 migrations (Drizzle)

- drizzle-kit 0.31 emits **flat** `migrations/0000_name.sql` plus a `migrations/meta/` journal.
  Wrangler applies top-level `*.sql` files and ignores `meta/`, so no `migrations_pattern` is
  needed. (drizzle-kit 1.0's per-folder layout would need `migrations_pattern`.)
- Workflow: edit `src/infrastructure/db/schema.ts` → `pnpm db:generate --name <slug>` → review SQL
  → `pnpm db:migrate:local`. Never use `drizzle-kit migrate/push`. Wrangler owns the
  `d1_migrations` table.
- Drizzle uses `casing: 'snake_case'` in both `drizzle.config.ts` and `createDb()`, so TS
  properties are camelCase and columns are snake_case.

## Durable Object

- `CampaignDO` runs its SQL schema migrations synchronously in the constructor (SQL storage is
  sync, and the constructor completes before any request is delivered). `blockConcurrencyWhile`
  isn't needed for that. The runner is in `src/do/schema-migrations.ts`, keyed by
  `meta.schema_version`.

## Tests

- `pnpm test` runs the root `vitest.config.ts` with `projects` pointing at each package's own config
  (`packages/*/vitest.config.ts`, `apps/web/vite.config.ts`, `apps/api/vitest.config.ts`).
  **Every package needs its own vitest config**: without one, `vitest` run inside the package
  walks up to the root config and fails to resolve the project globs.
- API unit tests run in Node and call `createApp().request(path, init, fakeEnv)`. They must not
  import `cloudflare:*`, so `src/index.ts` and the DO are tested in integration only.
- **Integration** (`tests/integration`): `cloudflareTest({ wrangler: { configPath } })` from
  `@cloudflare/vitest-plugin` 1.4.7. `readD1Migrations({ projectPath, migrationsDir })` runs in the
  config (Node). The result is passed as the `TEST_MIGRATIONS` miniflare binding and applied by
  `applyD1Migrations(env.DB, env.TEST_MIGRATIONS)` (from `cloudflare:test`) in a setup file. Tests
  use `import { env, exports } from 'cloudflare:workers'` and `exports.default.fetch(...)`.
  `SELF` and `cloudflare:test`'s `env` are deprecated. Types come from
  `"types": ["@cloudflare/vitest-plugin/types"]` plus the api's `worker-configuration.d.ts`.
- Integration runs twice (`tests/integration/vitest.shared.ts`): `vitest.config.ts` uses the real
  engine for every `*.test.ts`; `vitest.fake.config.ts` sets the `ENGINE=fake` miniflare binding for
  `*.fake.test.ts` (persistence/concurrency/idempotency tests that rely on tiny fake states).
  `runInDurableObject(stub, (i) => i.service.evictCache())` forces a cold reload from storage.
- Durable Object timings use `performance.now()`. On deployed Workers the clock only advances across
  I/O, so pure-CPU spans read about 0 there. Locally they are real.
- Web tests: jsdom + Testing Library + `@testing-library/jest-dom/vitest`.

## UI / shadcn

- `components.json` lives in **packages/ui**. Run `pnpm dlx shadcn@latest add <component>` from
  `packages/ui`. Components land in `packages/ui/src/components/` and are imported as
  `@whip/ui/components/<name>`. `cn` is at `@whip/ui/lib/utils`, and the package self-references
  via its `exports` map.
- Uses the unified `radix-ui` package (current shadcn practice), not individual `@radix-ui/*`.
- `tokens.css` defines the brand palette in a Tailwind v4 `@theme` and maps shadcn's semantic
  variables onto it. The web entry CSS imports it and adds `@source` for `packages/ui/src`.
- Fonts (Archivo, Inter) are the Google Fonts families, **self-hosted** via `@fontsource-variable/*`.
  This avoids a third-party request and keeps everything same-origin.

## Windows note

`pnpm add` inside a package failed with a pnpm path-casing bug (`D:\code` vs `D:\Code`). Edit
package.json and run `pnpm install` at the root instead.
